Changelog since v1.37.2

Changes by Kind

Ci

  • Fixed exclusive CPU cleanup when cgroups disappear during container cleanup. (#10468, @bitoku)

Dependency-Change

  • With stream_websockets and conmon-rs v1.2.0 or later, conmon-rs also serves port forwarding and its streaming sessions end after stream_idle_timeout of inactivity. Older conmon-rs versions disable stream_websockets, and pods started by them keep using the CRI-O streaming server. A conmon-rs server which does not exit on pod removal gets killed. A negative stream_idle_timeout fails the config validation. With conmon-rs, log_to_journald also logs containers to the journal, and exec syncs which conmon-rs could not start fail instead of returning exit code -2 or -3. (#10481, @openshift-cherrypick-robot)

Bug or Regression

  • Attaching to stdin once containers with conmon-rs no longer loses the output after the client closes its stdin. conmon-rs now gets the same environment as conmon (monitor_env) instead of the whole CRI-O environment, so variables set only on the CRI-O service (for example OTEL_* or proxy settings) no longer reach conmon-rs and the OCI runtime unless they are added to monitor_env. Attaching to a stdin once container through the conmon-rs streaming server now closes the container stdin when the client closes its stdin. (#10445, @openshift-cherrypick-robot)
  • Fix userns-mode when combined with a Kubelet supporting user namespaces. (#10429, @openshift-cherrypick-robot)
  • Fixed a possible crash and a panic of CRI-O with the pod runtime type (conmon-rs), and a leaked conmon-rs server after removing a pod with pod events enabled. (#10505, @openshift-cherrypick-robot)
  • When crio.service is restarted while containers are being created, an in-flight conmon process can still be killed and its crio-conmon-*.scope unit can still enter a failed state. That scope is now automatically garbage collected by systemd instead of persisting in systemctl --failed indefinitely. (#10451, @openshift-cherrypick-robot)

Uncategorized

  • Fixed CRI-O crash loops and stuck-Terminating pods caused by dead kata shims. (#10422, @openshift-cherrypick-robot)
  • Fixed a leak of the seccomp notifier file descriptor into the container monitor, which left the kernel’s seccomp notify listener attached with no reader after a CRI-O restart, causing process creation inside seccomp-notifier-armed containers to block indefinitely. (#10462, @openshift-cherrypick-robot)
